College Viva Guide

Twenty-five likely questions with answers grounded in this implementation.

01 What does this project do, in one sentence? ▼
It predicts whether a patient is likely to have coronary artery disease from 13 routine clinical measurements, using a Random Forest classifier trained on the Cleveland heart-disease dataset, served through a Flask web interface with a browser-side static build for GitHub Pages.
02 Why did you choose Random Forest instead of a single Decision Tree? ▼
A single tree is high-variance: a small change in the training data can change the tree completely. A Random Forest averages 100 trees, each trained on a bootstrap sample with a random subset of features per split, which reduces variance and gives a more stable probability estimate.
03 What is bagging and how is it used here? ▼
Bagging is Bootstrap AGGregatING: each of the 100 trees sees a different random sample drawn with replacement from the training rows. Their predictions are averaged (soft voting), which is why the model outputs a probability rather than a hard yes/no.
04 What is StandardScaler and why did you apply it? ▼
It standardises each feature to mean 0 and standard deviation 1 using z = (x - mean) / scale. The features here have wildly different units — cholesterol in the hundreds, oldpeak in single digits — so scaling puts them on a comparable footing and keeps distance-based splits and any linear baseline well conditioned.
05 Where do the mean and scale values come from? ▼
They are fitted only on the training split with fit_transform, then applied to the test split and to every live prediction with transform. Fitting on the full dataset would leak test information into training.
06 What is data leakage and did you avoid it? ▼
Leakage is when information from the test set influences training, inflating reported accuracy. It is avoided here by splitting first, fitting the scaler only on X_train, and training only on the scaled training rows.
07 Why a stratified train-test split? ▼
With 80/20 stratified splitting, the proportion of positive and negative cases is preserved in both parts. On a small, imbalanced dataset an ordinary random split can easily produce a test set with almost no negatives.
08 What is cross-validation and what did you report? ▼
5-fold cross-validation trains and evaluates five times, each time holding out a different fold, and averages the scores. train_model.py reports the mean and standard deviation of accuracy across the five folds.
09 Explain precision and recall in a medical screening context. ▼
Precision is the share of patients flagged as diseased who actually are diseased. Recall (sensitivity) is the share of truly diseased patients that the model catches. For screening, recall matters more — a false negative means a sick patient is sent home.
10 What does ROC-AUC mean? ▼
The ROC curve plots true-positive rate against false-positive rate across all thresholds. AUC is the probability that a randomly chosen diseased patient is ranked above a randomly chosen healthy one; 0.5 is random guessing and 1.0 is perfect separation.
11 What is a confusion matrix? What are TP, FP, FN and TN here? ▼
It cross-tabulates predicted against actual labels. TP is correctly flagged disease, TN is correctly cleared, FP is a false alarm, and FN is a missed case — the most costly error in this domain.
12 Your dataset is imbalanced. How did you handle it? ▼
The classifier is created with class_weight='balanced', which gives the minority class a proportionally larger weight in the impurity criterion, so the forest does not simply learn to predict the majority class.
13 What is overfitting and which hyperparameters control it? ▼
Overfitting is memorising the training rows so that test performance collapses. Here max_depth=6 caps tree depth, min_samples_split=4 and min_samples_leaf=2 stop splits on very few samples, and averaging 100 trees further smooths the result.
14 What is feature importance and how is it computed? ▼
Random Forest importance is the average decrease in node impurity (Gini) contributed by a feature across all trees, normalised to sum to 1. It is a global measure — it does not tell you the direction of the effect for an individual patient.
15 What is Gini impurity? ▼
Gini = 1 - sum(p_i^2) over the class proportions in a node. A perfectly pure node has Gini 0. Each split is chosen to maximise the impurity decrease, weighted by how many samples pass through the node.
16 Explain the key clinical features in the dataset. ▼
cp is chest-pain type (typical angina through asymptomatic), thalach is maximum heart rate achieved during exercise, oldpeak is ST depression induced by exercise relative to rest, ca is the number of major vessels coloured by fluoroscopy, and thal is the thallium stress-test result.
17 What is the target variable and how is it encoded? ▼
target is 1 for presence of heart disease and 0 for absence — a binary classification problem, which is why accuracy alone is not enough and precision, recall, F1 and ROC-AUC are also reported.
18 How does the Flask app serve a prediction? ▼
The app loads the joblib artifact once at start-up (model, scaler, feature order, metrics). A POST to /predict with the 13 features builds a numpy row, applies scaler.transform, calls predict and predict_proba, then returns the class, probability, risk tier and rule-based recommendations as JSON.
19 Why must the feature order be preserved at inference time? ▼
The scaler and the trees address features by column index. If the order at prediction time differs from training, every mean and threshold is applied to the wrong column and predictions become meaningless — which is why the artifact stores the feature list.
20 What is stored inside heart_disease_model.pkl? ▼
A dictionary containing the fitted RandomForestClassifier, the fitted StandardScaler, the ordered feature names and the evaluation metrics, serialised with joblib.
21 What is the difference between the Flask app and the GitHub Pages build? ▼
Pages serves static files only, so it cannot execute Python. The static build exports the trees and scaler to model.json and re-implements the traversal in JavaScript, producing identical probabilities in the browser; app.py remains the reference implementation for local use and the API.
22 How do you know the JavaScript version matches scikit-learn? ▼
For each tree we walk children_left/right using the same feature and threshold comparisons, take the class-1 fraction at the leaf and average over the 100 trees. On the test presets the result matches predict_proba to within about 1e-8, i.e. floating-point noise.
23 What are the main limitations of this project? ▼
The dataset is tiny (30 records in this build, 303 in full Cleveland), single-centre and decades old; the model is not calibrated or externally validated; feature importances are global only; and there is no handling of missing values beyond median imputation. It is a teaching demonstration, not a clinical device.
24 How would you improve it? ▼
Use the full 303-row Cleveland set or a larger modern cohort, tune hyperparameters with GridSearchCV, compare against gradient boosting and logistic regression, calibrate probabilities, add SHAP values for per-patient explanations, and validate on an external dataset before claiming any clinical utility.
25 Why is 100% test accuracy here not a good sign? ▼
The hold-out split has only 6 records, so a single error would move accuracy by nearly 17 percentage points. Perfect scores on a handful of samples indicate the test set is too small to be informative, not that the model is perfect.
